# Contributing

Open an issue before substantial changes, keep pull requests focused, and run
the checks listed in [docs/development.md](docs/development.md). Do not commit
environment files, credentials, hostnames, private network addresses, or data
from a real deployment.

Use Conventional Commit-style subjects where practical, such as `fix: correct
FTP passive port validation`. Explain user-visible behaviour changes and include
tests for server changes.
